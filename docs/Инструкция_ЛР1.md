# Инструкция по запуску лабораторной работы № 1

## 1\. Состав файлов

Для запуска необходимы:

- `lab01.ipynb` — основной Jupyter Notebook с кодом, тестовыми данными и результатами;  
- `requirements.txt` — список зависимостей.

Файл `products.db` отдельно прикладывать необязательно: база создаётся и заполняется непосредственно в ноутбуке. В нём присутствуют SQL-инициализация таблицы и список тестовых товаров. При первом запуске SQLite создаст файл `products.db` в рабочей папке ноутбука.

Отчёт по работе и эта инструкция прилагаются отдельно.

## 2\. Требования к окружению

- Python (в работе использовался Python 3.14);  
- VS Code с расширениями Python и Jupyter либо Jupyter Notebook;  
- доступ к университетскому серверу LLM `http://10.32.2.11:35000/v1`;  
- подключение к сети университета или университетскому VPN;  
- установленные библиотеки из `requirements.txt`.

## 3\. Подготовка окружения

1. Откройте папку проекта в IDE.  
2. Создайте и активируйте виртуальное окружение, если оно ещё не создано.

3. Установите зависимости:

```sh
pip install -r requirements.txt
```

4. Откройте `lab01.ipynb`.

5. В правом верхнем углу выберите Python kernel, в котором установлены зависимости проекта (в исходной работе использовалось окружение `nlp-lab`).

6. Убедитесь, что компьютер подключён к университетской сети VPN.

## 4\. Запуск ноутбука

1. Выполняйте ячейки последовательно сверху вниз.  
2. В первой ячейке с настройкой API введите токен, когда ноутбук запросит его.  
3. Убедитесь, что тестовый запрос к модели выполняется успешно.  
4. Продолжайте выполнение частей 1–5 по порядку.  
5. В части 2.4 режим thinking включается отдельно для сравнительного эксперимента.  
6. В части 3 создаётся и заполняется SQLite-база данных.  
7. В части 4 используются тестовые ответы `FakeListChatModel`; для этих проверок доступ к серверу модели не нужен.  
8. В части 5 выполняются тесты уточняющих запросов и сравнение количества входных токенов.

## 5\. Важное предупреждение о базе данных

**Не запускайте повторно ячейки создания и заполнения базы данных, если файл `products.db` уже существует и таблица заполнена.**

В ноутбуке используется `CREATE TABLE IF NOT EXISTS`, а затем выполняется `INSERT` тестового списка товаров. Повторный запуск ячейки заполнения добавит те же записи ещё раз: таблица не очищается, а ограничения уникальности для этих товаров не заданы. В результате в базе появятся дубликаты.

Практически это означает:

- при первом запуске в новой папке выполните ячейку создания таблицы и ячейку добавления тестовых товаров по одному разу;  
- при повторном запуске ноутбука с уже созданным `products.db` пропустите обе ячейки и переходите к проверке содержимого и последующим этапам;  
- перезапуск ядра Jupyter сам по себе не удаляет файл базы данных — SQLite-файл сохраняется на диске.

Если базу требуется создать заново, закройте соединение с ней, удалите старый `products.db` из папки проекта и только после этого выполните ячейки создания и заполнения один раз. Делайте это только если действительно хотите сбросить тестовую базу.
